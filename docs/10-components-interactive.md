# 10 - Components: interactive

> **Layout of this spec.** Each component (and blueprint) specified by this document lives in its own file under `components/<id>.md` (and `blueprints/<id>.md`). This document keeps the rules shared by the group plus one pointer per component. A reference elsewhere to "doc 10, <Component>" means that component's file.


Status: normative. Follows `00-decisions.md` (the ledger). Date: 2026-11-21.

### 0.2 Rules that apply to every component in this document

- **G-1** The fenced `html` blocks under "HTML contract" are normative. Line breaks and indentation inside them are not significant (`02-html-contract.md` C-7). Attribute order is not significant (`02-html-contract.md` 4.5).
- **G-2** A boolean attribute is written bare in this document (`popover`, `hidden`, `open`, `disabled`, `data-selected`). It is equal to the form with an empty value (`popover=""`) after canonicalisation.
- **G-3** Openers and closers are NOT parts of any component here (D-008 item 2, D-084). They are Button, IconButton or Link components from `09-components-foundation.md`, placed by the author. There is no `DialogClose`, `DrawerClose`, `DialogTrigger` or `PopoverTrigger` export. A fixture in this document therefore never contains an opener outside the root. Where a Dialog or Drawer fixture needs a closer INSIDE the root, the fixture's children are a plain native `<button type="button" commandfor="<id>" command="close">` with no `rp-` class, so that the fixture does not depend on the Button contract; in real pages the author uses Button or IconButton. The ONE exception is the Tooltip trigger: its markup is part of what UI SDK binds, so the Tooltip fixtures print the exact Button or IconButton contract for the stated props, including the prop `tooltip` (D-082, D-069 item 3).
- **G-4** An `<svg class="rp-icon" ...>` element shown in a contract is the Icon contract of `09-components-foundation.md` for the stated icon name. Its child elements are the content of `icons/<name>.svg`; the `<path>` data printed in this document is illustrative, and the fixture file generated by `pnpm gen` is the source of truth for it.
- **G-5** Every component MUST have the fixtures required by `02-html-contract.md` 11.5 (F-10 to F-17). The fixtures listed under each "HTML contract" are the complete required set for that component; an implementer MUST NOT drop one.
- **G-6** Manifest `fixtures[].generated` (REQUIRED, D-074) is `template` for Dialog, Drawer, Popover, Accordion, Carousel and QuantityInput, and `upgrade-snapshot` for Tooltip, Toast and Tabs (`02-html-contract.md` 11.4). The fixture source is the file `components/<id>/fixtures/<name>.html`; the manifest record holds `name`, `props`, `children`, `parts`, `hosts`, `mask`, `generated` (D-074).
- **G-7** Every component CSS file below is complete and normative. It was rendered in Chromium 157 against `css/tokens.css` of `03-styling-and-tokens.md` (evidence: `ripple/docs/research/spikes/components-interactive/`). An implementer copies it to `components/<id>/<id>.css` unchanged.
- **G-8** A prop marked "setting" in a "Liquid param" column is a schema setting of type `select` (`06-bindings.md` L-17). A setting exists only for a non-responsive enumerated prop with a default, at most three per block (D-038). A caller sets it with the same call-site syntax as a param (`size: 'lg'`). Schema label keys are the generated keys of D-038: `t:ripple.<component id>.name` for a root block, `t:ripple.<component id>.<part>_name` for a part block (part name in snake_case), `t:ripple.props.<prop liquid name>` for a setting label and `t:ripple.props.<value>` for an option label. Example, `blocks/dialog.liquid`: block name `t:ripple.dialog.name`; setting `size` labelled `t:ripple.props.size` with options `t:ripple.props.sm`, `t:ripple.props.md`, `t:ripple.props.lg`, `t:ripple.props.full`; `blocks/dialog-title.liquid`: block name `t:ripple.dialog.title_name`. The `{% schema %}` of every block in this document is generated from the manifest with exactly these keys; a "Locale keys" line under "Host notes" lists only the keys of strings the component PRINTS.
- **G-9** In every "Props" table, "React only" means the prop exists only in the React binding (D-036). It is absent from the manifest fixtures, from the Remix binding, and from Liquid.
- **G-10** Acceptance tests name their tier as "T<n>" where `<n>` is the tier number of D-063. Item `n` of a component's "Acceptance tests" list has the id `AT-<n>` inside that component (D-104); "test 4" and "acceptance test 4" in this document mean `AT-4` of the same component. The numbering MUST NOT be changed. Every component additionally MUST pass the generic tiers without a test being listed: T1 (`pnpm gen --check`), T2 (every fixture, every host), T3 (upgrade stability with the stated allow-list), T10 (size budgets, including the cap of 6,000 bytes minified per component CSS file, D-064). A test of a feature that is above the browser floor (D-081) MUST feature-detect and skip, not fail, on an engine without the feature.
- **G-11** The Remix binding of every component prints the host extras of `06-bindings.md` 7.3 (D-034): `data-rmx-key` only on a `ui-*` or `rp-*` ROOT (its value is the required `id`; on a root without a required `id` it is the value of the optional Remix-only prop `rmxKey`, and the attribute is omitted when `rmxKey` is unset); `data-rmx-preserve-attrs` on every element that an element or the browser writes to. The exact values per component are stated under "Host notes".
- **G-12** A component of this document that another component composes by contract keeps its class FIRST: Drawer is composed by CartDrawer (`class="rp-drawer rp-cart-drawer"`) and MobileNav (`class="rp-drawer rp-mobile-nav"`); the Dialog markup is composed by ProductGallery's lightbox; the Carousel markup by ProductGallery and FeaturedCollection (D-070). The CSS files and the checker rule selectors of this document therefore MUST NOT assume that their class is the only `rp-` class on an element: every selector here matches by one class token (`.rp-drawer`, `rp-dialog.rp-drawer`), never by an exact `class` attribute value.
- **G-13** In every Liquid block and snippet of this document `{{ attributes }}` is printed LAST in the root's start tag, after every contract attribute (D-035, `06-bindings.md` L-18). In TSX, rest props are spread FIRST. A caller attribute can therefore never override a contract attribute. A Ripple hook attribute that has a prop MUST be set through the prop, never through rest props or `attributes`: `data-rp-open` (prop `dialog` of Link, Button, IconButton), `data-rp-field`, and `aria-describedby` plus `data-slot` on a tooltip trigger (prop `tooltip`).
- **G-14** In every "State and attributes" table the "Written by" value is one of `server`, `element`, `browser` (the manifest `state[].writer` values). "element (UI SDK)" and "element (`rp-<tag>`)" name which element code writes; both are `writer: "element"`. Remix `data-rmx-preserve-attrs` lists are derived from the rows whose writer is `element` or `browser` (D-034).
- **G-15** In every "Upgrade allow-list" block the JSON is the value of the manifest key `upgradeAllow` for that component: an array of `UpgradeAllowEntry` objects with the keys `select`, `attrs`, `childList`, `text`, `subtree`, `reason` (D-071; `02-html-contract.md` 7.2). `reason` is REQUIRED; the other optional keys are omitted when they have their default (`attrs: []`, `false`). A write that sets an attribute to the value it already has is not a mutation (D-002): the tier 3 judge reports it as information, it does not fail, and it MUST NOT have an entry.

### 0.3 Facts in files owned by other documents that the contracts below rely on

Decided: D-021, D-025, D-080, D-105. The four items are ledger text; `03-styling-and-tokens.md` (items 1, 3, 4) and `04-elements.md` (item 2) own the files and copy this text.

1. `css/base.css` contains this block inside its `@layer ui-sdk { ... }` block, directly after the `[hidden]` rule (D-021 item (d), D-025; needed by Tabs; reason and evidence under Tabs, "Behaviour without JavaScript"). It is the second and last `!important` rule Ripple writes:

   ```css
   @media (scripting: none) {
     ui-tabs-panel[hidden] {
       display: block !important;
     }
     ui-tabs-list {
       display: none !important;
     }
   }
   ```

2. Every `rp-*` tag has `display: block` in the generated display region of `base.css` (D-080; manifest key `elements.<tag>.display`). `rp-dialog` additionally has `position: absolute; inline-size: 0; block-size: 0`, so the full rule is `rp-dialog { display: block; position: absolute; inline-size: 0; block-size: 0; }`. The component CSS of Dialog and Drawer sets no `display` on the root. Component CSS MUST NOT set `display: contents` or `display: none` on a custom element root (D-080 item 3); `carousel.css` and `quantity-input.css` set `grid` and `inline-flex` on their roots, which is allowed.
3. `lintComponentCss` (`03-styling-and-tokens.md` 7.9) reads the root class from manifest `root.class` (QuantityInput: `rp-quantity`) and accepts the selectors `:popover-open`, `::-webkit-inner-spin-button`, `[data-starting-style]`, `[data-ending-style]`, and `.rp-toast :where(<tag or tag[attribute]>)` (D-105 items 1 and 2; D-021 item (e)).
4. `03-styling-and-tokens.md` 7.7 (reserved UI SDK attribute names) exempts a `data-<prop>` attribute that the component's own manifest defines as a prop, selected together with the component's own class (D-024 item (b), D-105 item 3). Two files of this document use the exemption: `popover.css` (`data-side`, `data-align`, D-010) and `carousel.css` (`data-columns`, D-016). The rules of `props.css` for `data-align` and `data-columns` are scoped with `:where()` to layout components and do not match these roots.
