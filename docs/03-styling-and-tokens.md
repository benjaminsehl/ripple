Rules:

1. Ripple MUST NOT ship a CSS rule outside a cascade layer. The only unlayered CSS on a Ripple page is the host's token bridge (section 3.8).
2. Ripple CSS MUST be plain CSS. These MUST NOT appear in any file above: `@apply`, `@utility`, `@variant`, `@custom-variant`, `theme(`, `@import` (except in the scaffolded `ripple.css` of section 5.2), CSS nesting (`&` or a rule inside a style rule), Sass or Less syntax, `@property`.
3. `!important` MUST appear exactly once in all Ripple CSS: the `[hidden]` rule in `css/base.css`.
4. The authored file is the shipped file. No build step transforms Ripple CSS: scaffolded files are copied, and the prebuilt `browser/ripple.css` is a plain concatenation (section 5.4).
5. Generated files (`props.css`, `theme.css`, the two regions of `base.css`) are committed. `pnpm gen --check` MUST fail when a committed generated file differs from the generator output.

## 2. Cascade layers

### 2.1 The layer statement

`css/layers.css` is exactly these two lines:

```css
@layer ui-sdk, theme, base, rp, components, rmx, utilities;
@layer rp.tokens, rp.base, rp.components, rp.props;
```

These two statements MUST be the first CSS statements of:

- the scaffolded `ripple.css` (section 5.2),
- the prebuilt `browser/ripple.css`,
- the Liquid asset `assets/ripple.css`.

In a project that compiles Tailwind, the file that starts with these statements MUST be imported before `@import "tailwindcss"`. Verified failure when it comes after: Tailwind's own `@layer theme, base, components, utilities;` is seen first, `ui-sdk` and `rp` are appended after `utilities`, and Ripple silently beats utilities (`ripple/docs/research/styling-spike.md` 1.3).

Tailwind 4.3.5 emits one more statement, `@layer properties;`, before everything else in its compiled output. This is expected and harmless: `properties` becomes the earliest layer and holds only Tailwind's `--tw-*` registrations (verified in `ripple/docs/research/spikes/styling-doc03/tw/`).

### 2.2 Who writes where

| Order | Layer | Owner | Content |
|---:|---|---|---|
| 1 | `ui-sdk` | UI SDK runtime; Ripple (one rule) | UI SDK's injected defaults (`uisdk/packages/core/src/foundation/platform/style.ts`); Ripple's `[hidden]` rule |
| 2 | `theme` | Tailwind | Tailwind's `:root` variables |
| 3 | `base` | Tailwind | Preflight |
| 4 | `rp.tokens` | Ripple | `tokens.css` |
| 5 | `rp.base` | Ripple | `base.css`: reset, scheme painting, focus ring, keyframes, static display rules |
| 6 | `rp.components` | Ripple | one file per component |
| 7 | `rp.props` | Ripple | `props.css`; the script-state rules of `base.css` |
| 8 | `components` | the project | project component CSS; beats Ripple |
| 9 | `rmx` | Remix 3 | rules emitted by Remix `css()` |
| 10 | `utilities` | Tailwind | utilities; beat everything layered |

Consequences that other documents rely on:

1. A Tailwind utility in `class` always overrides a Ripple prop and Ripple component CSS. This is the escape hatch.
2. A layout prop (`data-p`) overrides a component's own declaration of the same property, because `rp.props` follows `rp.components`.
3. Ripple tokens override Tailwind's default theme variables regardless of file order, because `rp.tokens` follows `theme`.
4. Ripple component CSS overrides Tailwind preflight, so a component renders the same with and without Tailwind (acceptance test A-12).
5. Unlayered CSS beats every layer. Project CSS that must not override Ripple MUST be placed in `@layer components` or `@layer utilities`.

Ripple MUST write only in `ui-sdk` (the one `[hidden]` rule) and in the four `rp.*` sublayers. Ripple MUST NOT write in `theme`, `base`, `components`, `rmx` or `utilities`.

## 3. Tokens

### 3.1 Naming

| Kind | Pattern | Declared in | Example |
|---|---|---|---|
| Dial | `--rp-<name>` | `tokens.css` sections 1 and 2 | `--rp-radius` |
| Token in a Tailwind v4 theme namespace | Tailwind's name: `--color-*`, `--spacing`, `--spacing-*`, `--radius-*`, `--text-*`, `--font-*` (includes `--font-weight-*`), `--shadow-*`, `--ease-*`, `--container-*`, `--breakpoint-*` | `tokens.css` section 3 | `--color-primary` |
| Other global token | `--rp-<group>-<name>` | `tokens.css` section 3 | `--rp-duration-fast` |
| Generator input | `--rp-space-steps`, `--breakpoint-*` | `tokens.css` section 1 | |
| Component public variable | `--rp-<component id>-<name>` | the component's CSS file | `--rp-button-height` |
| Component private variable | `--_<name>` | the component's CSS file | `--_bg` |

`tokens.css` is the only file in which a token value is written. A component CSS file MUST NOT declare a name from the first four rows.

### 3.2 Dials

A dial is an input. Every other token derives from the dials. A project restyles Ripple by changing dials, not derived tokens.

| Dial | Default | Allowed values | Effect |
|---|---|---|---|
| `--rp-background` | `oklch(1 0 0)` | any colour inside the sRGB gamut | page and surface background; one end of every neutral mix |
| `--rp-foreground` | `oklch(0.21 0.006 286)` | any colour inside the sRGB gamut | text colour; the other end of every neutral mix |
| `--rp-brand` | `oklch(0.21 0.006 286)` | any colour inside the sRGB gamut | `--color-primary` |
| `--rp-brand-foreground` | unset (`initial`) | any colour, or unset | optional; when unset the text colour on the brand is computed (section 3.5 rule 4) |
| `--rp-accent` | unset | any colour, or unset | optional; feeds `--color-link`; when unset links use `--rp-foreground` |
| `--rp-radius` | `0.5rem` | a length from `0` to `1.5rem` | every `--radius-*` token |
| `--rp-density` | `1` | a number from `0.75` to `1.25` | multiplies `--spacing` |
| `--rp-text-scale` | `1.2` | a number from `1.125` to `1.333` | ratio between type steps above `--text-base` |
| `--rp-font-body` | `ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji"` | a font-family list | `--font-sans` |
| `--rp-font-heading` | unset | a font-family list, or unset | `--font-heading`; when unset headings use `--rp-font-body` |

Semantic radius tokens (`--radius-control`, `--radius-field`, `--radius-surface`) are not dials, but they MAY be overridden directly to obtain shapes the single radius dial cannot express (for example pill buttons with rounded cards: `--radius-control: 9999px`). They are the only derived tokens a project SHOULD override directly; the Liquid bridge additionally overrides `--color-muted` (section 3.8).

### 3.4 Token reference

Values at the default dials. "px" assumes a 16 px root font size.

**Colour roles** (names fixed by D-027). Each `X-foreground` is the text colour on `X`.

| Token | Definition | Use |
|---|---|---|
| `--color-background` | `--rp-background` | page background |
| `--color-foreground` | `--rp-foreground` | body text |
| `--color-card`, `--color-card-foreground` | `--rp-background`, `--rp-foreground` | Card and other raised surfaces |
| `--color-popover`, `--color-popover-foreground` | `--rp-background`, `--rp-foreground` | Popover, Dialog, Drawer, Tooltip surfaces |
| `--color-primary`, `--color-primary-foreground` | `--rp-brand`; computed black or white, or `--rp-brand-foreground` | primary actions |
| `--color-secondary`, `--color-secondary-foreground` | 9% foreground in background; `--rp-foreground` | secondary actions |
| `--color-muted`, `--color-muted-foreground` | 5% foreground in background; 64% foreground in background | subdued surfaces; secondary text |
| `--color-accent`, `--color-accent-foreground` | 8% foreground in background; `--rp-foreground` | hover and selected surface (shadcn meaning; NOT the brand accent) |
| `--color-border` | 14% foreground in background | decorative borders, separators |
| `--color-input` | 45% foreground in background | borders of form controls (meets 3:1) |
| `--color-ring` | `--rp-foreground` | focus ring |
| `--color-overlay` | `oklch(0 0 0 / 0.5)` | dialog backdrop |
| `--color-link` | `--rp-accent`, else `--rp-foreground` | links |
| `--color-destructive`, `--color-destructive-foreground` | red; follows the scheme background | errors, destructive actions |
| `--color-success`, `--color-success-foreground` | green; follows the scheme background | success |
| `--color-warning`, `--color-warning-foreground` | amber; follows the scheme background | warnings |
| `--color-info`, `--color-info-foreground` | blue; follows the scheme background | information |
| `--color-sale`, `--color-sale-foreground` | `--color-destructive`, `--color-destructive-foreground` | sale prices and badges |

The word for the red role is `destructive` everywhere. `critical`, `danger` and `error` MUST NOT be used as token, tone or variant names.

### 3.5 Derivation rules

1. **Derived tokens are declared on `:root, [data-scheme]`.** A `var()` is resolved on the element that declares the property, and descendants inherit the resolved value. A derived token declared on `:root` alone would not change when a descendant changes a dial (verified counter-test, `ripple/docs/research/styling-spike.md` 3.2).
2. **Any element that sets a dial MUST carry `data-scheme="<name>"`.** This includes elements that change only `--rp-radius`, `--rp-density` or `--rp-text-scale`.

   ```html
   <section data-scheme="dark">...</section>
   <section data-scheme="compact" style="--rp-density: 0.75; --rp-radius: 0">...</section>
   ```

   An element with `data-scheme` is painted with `--color-background` and `--color-foreground` by `base.css`.
3. **Scheme blocks use literal values.** A scheme MUST NOT define one dial from another (`--rp-background: var(--rp-foreground)` together with the reverse is a cycle and both become invalid).
4. **Text colour on the brand.** Where relative colour syntax is supported, `--color-primary-foreground` is black or white, whichever has the higher WCAG contrast against `--rp-brand` (black when the relative luminance `y` exceeds 0.179). Verified: correct for all 1,385 in-gamut samples of a sweep, minimum contrast 4.58:1 (`ripple/docs/research/styling-spike.md` 3.3). Where it is not supported the value is `--rp-brand-foreground`, or white when that is unset. `--rp-brand-foreground` always wins when set.
5. **Status colours follow the scheme background.** Where relative colour syntax is supported, the lightness of `--color-destructive`, `--color-success`, `--color-warning`, `--color-info` and of `--color-destructive-foreground` switches at background lightness 0.6. Where it is not supported, section 3 of `tokens.css` gives the light values and section 4 gives the dark values for `[data-scheme="dark"]`.
6. **Every feature above the browser floor is inside `@supports`, after a static declaration of the same tokens** (sections 5 and 6 of `tokens.css`).
7. **The section order of `tokens.css` is fixed** (1 to 6). Sections 4, 5 and 6 override section 3 by source order at equal specificity; reordering breaks the fallbacks.
8. A dial colour outside the sRGB gamut is not guaranteed to produce a readable `--color-primary-foreground`. The checker SHOULD warn (rule owned by `07-manifest-registry-cli.md`).

### 3.6 Schemes and dark mode

1. A **scheme** is a named set of colour dial values applied with `data-scheme="<name>"` on any element, including `<html>`. Built-in names: `light` and `dark`. `light` is also the value of `:root`.
2. Every scheme block MUST set these five declarations and MUST NOT set a derived token: `--rp-background`, `--rp-foreground`, `--rp-brand`, `--rp-brand-foreground`, `color-scheme`. `--rp-brand-foreground` is `initial` when the scheme wants the computed value. If any scheme block sets `--rp-accent`, every scheme block MUST set it (use `initial` for "unset"). Reason: a scheme nested inside another scheme inherits every dial it does not set.
3. Schemes nest. `<div data-scheme="light">` inside `<section data-scheme="dark">` renders the light values (verified).
4. Dark mode is opt-in. A page is dark when `<html data-scheme="dark">` is printed by the host. Ripple ships no scheme that follows the operating system setting.
5. A project adds a scheme by adding ONE block to section 2 of `tokens.css`, with a literal value for each dial:

   ```css
   [data-scheme="sand"] {
     --rp-background: oklch(0.96 0.02 85);
     --rp-foreground: oklch(0.25 0.02 60);
     --rp-brand: oklch(0.45 0.12 40);
     --rp-brand-foreground: initial;
     color-scheme: light;
   }
   ```

   A project scheme whose background lightness is below 0.6 MUST also add its selector to the selector list of section 4 of `tokens.css` (`[data-scheme="dark"], [data-scheme="<name>"] { ... }`).
6. A project that wants the operating system setting to choose the scheme adds this block to section 2 and prints `<html data-scheme="system">`. This block is NOT part of the default `tokens.css`:

   ```css
   @media (prefers-color-scheme: dark) {
     [data-scheme="system"] {
       --rp-background: oklch(0.17 0.006 286);
       --rp-foreground: oklch(0.97 0 0);
       --rp-brand: oklch(0.97 0 0);
       --rp-brand-foreground: oklch(0.17 0.006 286);
       color-scheme: dark;
     }
   }
   ```

7. The `scheme` prop (`00-decisions.md` 6.3) prints `data-scheme="<value>"` on the component root. Component CSS MUST NOT contain a selector with `data-scheme`: a component looks right in every scheme because it reads only derived tokens.
8. `color-scheme` is set by each scheme block so that native controls, scrollbars and the default canvas follow the scheme.

### 3.7 Changing the scales

| Change | How | Regeneration |
|---|---|---|
| Any token value, dial default, new scheme | edit `tokens.css` | `theme.css` MUST be regenerated when a token in a Tailwind namespace is added, removed or renamed (its values are only fallbacks) |
| Spacing size | change `--rp-density` or `--spacing` | none |
| Space steps | edit `--rp-space-steps` in `tokens.css` | `props.css` |
| Breakpoint names or widths | edit `--breakpoint-*` in `tokens.css` | `props.css`, `theme.css`; the project MUST also update every `@media (min-width: ...)` literal in its component CSS (lint rule CSS-16) |
| Type ratio, radius | change the dial | none |

Token names MUST NOT change. `--rp-space-steps` is read only by the generator; no CSS consumes it.

In the Ripple repository regeneration is `pnpm gen`. In a project, `ripple add` and `ripple upgrade` MUST regenerate `theme.css` and `props.css` from the project's own `tokens.css` on every run, using the generator functions of sections 5.1 and 6.3 (command behaviour is specified in `07-manifest-registry-cli.md`). `props.css` SHOULD stay at or below 100 rules per attribute name per file (currently 96 for a spacing prop); each added space step adds 48 rules.

### 3.8 The host token bridge

A host MAY set dials at run time by printing ONE unlayered `<style>` element after the Ripple stylesheet. This is the only unlayered CSS on a Ripple page. Its required shape:

```html
<style>
  :root {
    --rp-radius: 0.5rem;
    --rp-density: 1;
    --rp-text-scale: 1.2;
    --rp-font-body: "Inter", sans-serif;
    --rp-font-heading: "Fraunces", serif;
  }
  :root,
  [data-scheme="light"] {
    --rp-background: #ffffff;
    --rp-foreground: #1a1a1a;
    --rp-brand: #1a1a1a;
    --rp-accent: #0b57d0;
    --color-muted: #f4f4f5;
  }
</style>
```

Rules:

1. Non-colour dials go in the `:root` rule. Colour dials go in the `:root, [data-scheme="light"]` rule, so that a `scheme="light"` component inside a dark section shows the merchant's colours and not the stock ones.
2. The bridge MUST print only dials, plus the three semantic radius tokens and `--color-muted` where the host has a setting for them. It MUST NOT print any other derived token.
3. A declaration whose setting is blank MUST be omitted (not printed with an empty value).
4. The bridge MAY print `--rp-brand-foreground` in the colour rule. When it does not, the computed value applies.
5. On Liquid the bridge is `snippets/rp-tokens.liquid`. Setting ids and palette slots are fixed by D-026 item 5: `rp_palette.surface` to `--rp-background`, `rp_palette.on_surface` to `--rp-foreground`, `rp_palette.interactive` to `--rp-brand`, `rp_palette.surface_2` to `--color-muted`, `rp_palette.accent` to `--rp-accent`, `rp_radius` to `--rp-radius`, `rp_density` to `--rp-density`, `rp_text_scale` to `--rp-text-scale`, `rp_font_body` to `--rp-font-body`, `rp_font_heading` to `--rp-font-heading`. The values printed MUST be inside the "Allowed values" column of section 3.2. The Liquid source and the settings schema are specified in `14-liquid-theme.md`.

### 4.2 Rules

1. **Hidden.** The `[hidden]` rule is in layer `ui-sdk` and is `!important`, so it beats every `display` declaration in every later layer, before and after element upgrade. Component CSS MUST NOT try to show an element that has the `hidden` attribute; the owner removes the attribute.
2. **Reset.** `base.css` resets only what the list above shows. It MUST NOT grow into a full reset. Each component resets what it needs on its own root (`margin`, `padding`, `border`, `background`, `font`, `list-style`, `text-decoration`), so that it renders identically with and without Tailwind preflight.
3. **Scheme painting.** `body` and every `[data-scheme]` element get `background-color` and `color` from the derived tokens.
4. **Focus ring.** Section 11.
5. **Shared keyframes.** `rp-spin` and `rp-pulse` are the only keyframes in `base.css`. A component that needs another animation defines `@keyframes rp-<component id>-<name>` in its own file.
6. **Static display rules** (region `display`). An undefined custom element is `display: inline`. Without a static rule, layout changes when the element upgrades (measured: 50 px shift, CLS 0.014, `ripple/docs/research/styling-spike.md` 5.1). The region holds one rule per display value. Selectors are `:where(...)` so that a component class can override the value.
7. **Script-state rules** (region `script-state`). They implement `data-rp-js` (`00-decisions.md` D-021 item 4). They are in layer `rp.props`, not `rp.base`: a control that carries `data-rp-js` usually also has a component class whose `display` is declared in `rp.components`, and a rule in the earlier layer `rp.base` would lose to it (verified: with the rules in `rp.props`, a `.rp-button` with `data-rp-js="overlay"` computes `display: none` before definition and `inline-flex` after).
8. These three rules are the only CSS in Ripple that selects a `data-rp-*` attribute.
9. No rule may hide content or a working native control (link, submit button, input) before upgrade. A control hidden by `data-rp-js="inflow"` or `"overlay"` stays hidden when the script never loads; everything else works.

`src/gen/display-css.ts` (complete; verified to reproduce the regions of section 4.1 byte for byte):

```ts
// Generates the two marker regions of css/base.css from the list of custom elements.

export interface ElementDisplay {
  /** Custom element tag, for example "rp-dialog" or "ui-tabs-panel". */
  tag: string
  /** Static display value. Only these two values are allowed. */
  display: "block" | "contents"
}

const INDENT = "  "

function rule(selector: string, declaration: string): string {
  return `${INDENT}${selector} {\n${INDENT}${INDENT}${declaration};\n${INDENT}}`
}

/** Body of the `display` region: one rule per display value, tags sorted by name. */
export function generateDisplayRegion(elements: ElementDisplay[]): string {
  const rules: string[] = []
  for (const display of ["contents", "block"] as const) {
    const tags = elements
      .filter((element) => element.display === display)
      .map((element) => element.tag)
      .sort()
    if (tags.length > 0) rules.push(rule(`:where(${tags.join(", ")})`, `display: ${display}`))
  }
  return rules.join("\n")
}

/** Body of the `script-state` region: three rules that name every rp-* tag, sorted by name. */
export function generateScriptStateRegion(elements: ElementDisplay[]): string {
  const tags = elements
    .map((element) => element.tag)
    .filter((tag) => tag.startsWith("rp-"))
    .sort()
  if (tags.length === 0) return ""
  const owners = `:where(${tags.join(", ")})`
  return [
    rule(`${owners}:not(:defined) [data-rp-js="inflow"]`, "visibility: hidden"),
    rule(`${owners}:not(:defined) [data-rp-js="overlay"]`, "display: none"),
    rule(`${owners}:defined [data-rp-js="fallback"]`, "display: none"),
  ].join("\n")
}

/** Replaces the text between the start and end markers of a region. Throws when a marker is missing. */
export function replaceRegion(css: string, name: string, body: string): string {
  const start = `${INDENT}/* ripple:start ${name} */\n`
  const end = `${INDENT}/* ripple:end ${name} */`
  const from = css.indexOf(start)
  const to = css.indexOf(end)
  if (from === -1 || to === -1 || to < from) throw new Error(`base.css: region "${name}" not found`)
  return css.slice(0, from + start.length) + (body === "" ? "" : body + "\n") + css.slice(to)
}

export function generateBaseCss(baseCss: string, elements: ElementDisplay[]): string {
  const withDisplay = replaceRegion(baseCss, "display", generateDisplayRegion(elements))
  return replaceRegion(withDisplay, "script-state", generateScriptStateRegion(elements))
}
```

#### Fallback (SPIKE-02)

When SPIKE-02 finds that the Liquid platform wraps block or partial output in an element, ONE hand-written rule is added to `css/base.css` in layer `rp.base`, directly before the `display` region: `:where(<wrapper selector recorded by SPIKE-02 in 14-liquid-theme.md>) { display: contents; }`. Nothing else in this document changes.

`pnpm gen` builds the `ElementDisplay[]` list from the manifest (every tag in every component's `root.elements` and parts, with its display value; the manifest key that stores the value is defined in `07-manifest-registry-cli.md`) and writes `generateBaseCss(<current css/base.css>, elements)` back to `css/base.css`.

## 5. Tailwind v4 integration and the no-build output

### 5.1 `theme.css`

`theme.css` teaches Tailwind the names of Ripple tokens. It is one `@theme reference { ... }` block. Facts verified with `tailwindcss` 4.3.5:

1. With `reference`, Tailwind emits no `:root` variable for the token. A utility compiles to `var(--name, <value in the block>)`, for example `.rounded-md { border-radius: var(--radius-md, calc(var(--rp-radius) * 0.75)); }`. The value in the block is only a fallback; the live value comes from `tokens.css`. Utilities therefore follow dials at run time (verified: `--rp-radius: 1rem` changes `rounded-md` from 6 px to 12 px).
2. A token whose value in the block is `initial` produces no utility. Every token MUST have a real value. The generator throws on `initial`.
3. `--breakpoint-*` in the block defines Tailwind's `sm:` to `2xl:` variants, so `class="md:hidden"` and `data-hidden="md:true"` switch at the same width.
4. `shadow-*` utilities inline the fallback value and do not follow a run-time change of `--shadow-*`. Ripple component CSS reads `var(--shadow-*)` and does follow it.
5. Tokens with no Tailwind namespace are exposed through aliases: `--z-index-raised|sticky|overlay|toast` (utilities `z-raised`, `z-sticky`, `z-overlay`, `z-toast`) and `--transition-duration-fast|base|slow` (utilities `duration-fast`, `duration-base`, `duration-slow`). The theme keys `--z-index` and `--transition-duration` are read by `tailwindcss` 4.3.5 (`dist/lib.mjs`) but are not in Tailwind's documentation as far as this investigation found: their status as a supported contract is UNVERIFIED. Acceptance test A-10 pins the behaviour; if a Tailwind upgrade breaks it, remove the seven alias lines (no Ripple CSS depends on them).

`src/gen/tokens-source.ts` (complete; shared by both generators):

```ts
// Reads scale inputs from the text of tokens.css. No dependencies.

  /** Breakpoint name to min-width, ascending by width. Example: { sm: "40rem" }. */
  breakpoints: Record<string, string>
  /** Space steps as written in --rp-space-steps. Example: ["0", "0.5", "1"]. */
  spaceSteps: string[]
}

export interface Declaration {
  name: string
  value: string
}

export function stripComments(css: string): string {
  return css.replace(/\/\*[\s\S]*?\*\//g, "")
}

function toRem(length: string): number {
  const match = /^([0-9.]+)(rem|px)$/.exec(length)
  if (!match) throw new Error(`tokens.css: breakpoint value "${length}" must be in rem or px`)
  return match[2] === "rem" ? Number(match[1]) : Number(match[1]) / 16
}

export function readScales(tokensCss: string): Scales {
  const css = stripComments(tokensCss)
  const found: [string, string][] = []
  for (const match of css.matchAll(/--breakpoint-([a-z0-9]+)\s*:\s*([^;]+);/g)) {
    found.push([match[1], match[2].trim()])
  }
  if (found.length === 0) throw new Error("tokens.css: no --breakpoint-* declaration found")
  found.sort((a, b) => toRem(a[1]) - toRem(b[1]))
  const steps = /--rp-space-steps\s*:\s*([^;]+);/.exec(css)
  if (!steps) throw new Error("tokens.css: --rp-space-steps not found")
  const spaceSteps = steps[1].trim().split(/\s+/)
  for (const step of spaceSteps) {
    if (!/^[0-9]+(\.[0-9]+)?$/.test(step)) throw new Error(`tokens.css: invalid space step "${step}"`)
  }
  return { breakpoints: Object.fromEntries(found), spaceSteps }
}

/**
 * Returns the declarations of every style rule inside `@layer rp.tokens` that is NOT inside
 * `@supports` or `@media`, in source order.
 */
export function readStaticDeclarations(tokensCss: string): Declaration[] {
  const css = stripComments(tokensCss)
  const out: Declaration[] = []
  const stack: string[] = []
  let prelude = ""
  let body = ""
  for (const char of css) {
    if (char === "{") {
      stack.push(prelude.trim())
      prelude = ""
      body = ""
    } else if (char === "}") {
      const own = stack.pop() ?? ""
      const conditional = stack.some((p) => p.startsWith("@supports") || p.startsWith("@media"))
      if (!own.startsWith("@") && !conditional) {
        for (const match of body.matchAll(/(--[A-Za-z0-9_-]+)\s*:\s*([^;]+);/g)) {
          out.push({ name: match[1], value: match[2].replace(/\s+/g, " ").trim() })
        }
      }
      prelude = ""
      body = ""
    } else {
      prelude += char
      body += char
    }
  }
  return out
}
```

## 6. Layout props (`props.css`)

### 6.1 Grammar and attributes

The value grammar is fixed by `00-decisions.md` D-028 item 2; printing rules are in `02-html-contract.md` and `06-bindings.md`. For CSS: a responsive prop is ONE attribute holding space-separated tokens, each `value` or `breakpoint:value`, matched with the `~=` attribute operator.

| Attribute | Values | CSS property | Scope of the selector |
|---|---|---|---|
| `data-gap` | space steps | `gap` | any element |
| `data-gap-x` | space steps | `column-gap` | any element |
| `data-gap-y` | space steps | `row-gap` | any element |
| `data-p` | space steps | `padding` | any element |
| `data-px` | space steps | `padding-inline` | any element |
| `data-py` | space steps | `padding-block` | any element |
| `data-pt` | space steps | `padding-block-start` | any element |
| `data-pb` | space steps | `padding-block-end` | any element |
| `data-direction` | `row column` | `flex-direction` | `:where(.rp-stack, .rp-inline)` |
| `data-wrap` | `wrap nowrap` | `flex-wrap` | `:where(.rp-stack, .rp-inline)` |
| `data-align` | `start center end stretch baseline` | `align-items` (`flex-start`, `center`, `flex-end`, `stretch`, `baseline`) | `:where(.rp-stack, .rp-inline, .rp-grid)` |
| `data-justify` | `start center end between` | `justify-content` (`flex-start`, `center`, `flex-end`, `space-between`) | `:where(.rp-stack, .rp-inline, .rp-grid)` |
| `data-columns` | `1 2 3 4 5 6 12` | `grid-template-columns: repeat(n, minmax(0, 1fr))` | `:where(.rp-grid)` |
| `data-text-align` | `start center end` | `text-align` | `:where(.rp-heading, .rp-text, .rp-stack)` |
| `data-span` | `1 2 3 4 5 6 full` | `grid-column: span n / span n`; `full` is `1 / -1` | any element |
| `data-hidden` | `true false` | `display: none`; `false` is `display: revert-layer` | any element |

There are no margin props.

### 6.2 Generator rules

1. One block for the unprefixed tokens, then one `@media (min-width: <value>)` block per breakpoint in ascending width.
2. Inside every block the attributes appear in the order of the table in 6.1 (shorthand before longhand). This reproduces Tailwind's result for mixed props: `data-p="2 md:6" data-px="4"` gives inline padding 16 px below `md` and 24 px from `md` (verified). Grouping by attribute first gives a wrong result.
3. Every selector has specificity (0,1,0). Scopes use `:where()`.
4. The attribute value in the selector is always quoted.
5. Logical properties only.
6. `data-direction`, `data-wrap`, `data-align`, `data-justify`, `data-columns` and `data-text-align` are scoped as in the table. Reason for `data-align`: UI SDK writes `data-align="start|center|end"` on positioned popup content (`uisdk/packages/core/src/foundation/platform/position.ts`); an unscoped rule would set `align-items` on every tooltip.
7. `data-hidden="false"` uses `display: revert-layer`, which returns the element to the `display` its component gave it in `rp.components`.
8. The file is one `@layer rp.props { ... }` block.
9. The generator fails when a prop attribute name equals a UI SDK state attribute (`00-decisions.md` 4.3, last item) and has an empty scope.

### 6.3 `src/gen/props-css.ts` (complete)

```ts
// Generates css/props.css from the text of tokens.css. No dependencies.
import { readScales } from "./tokens-source.ts"

/** Ordered list of [token, declaration]. */
type ValueMap = [string, string][]

interface PropRule {
  /** Attribute name without the data- prefix. */
  attr: string
  /** Selector prefix, or "" for unscoped props. Always a :where() so specificity stays (0,1,0). */
  scope: string
  /** Token to declaration. */
  values: ValueMap
}

const STACK_INLINE = ":where(.rp-stack, .rp-inline)"
const STACK_INLINE_GRID = ":where(.rp-stack, .rp-inline, .rp-grid)"
const GRID = ":where(.rp-grid)"
const TEXT = ":where(.rp-heading, .rp-text, .rp-stack)"

function space(steps: string[], property: string): ValueMap {
  return steps.map((step) => [
    step,
    step === "0" ? `${property}: 0` : `${property}: calc(var(--spacing) * ${step})`,
  ])
}

function numbered(values: string[], declaration: (n: string) => string): ValueMap {
  return values.map((value) => [value, declaration(value)])
}

/** The order of this array is the cascade order inside one breakpoint block. Do not reorder. */
export function propRules(spaceSteps: string[]): PropRule[] {
  return [
    { attr: "gap", scope: "", values: space(spaceSteps, "gap") },
    { attr: "gap-x", scope: "", values: space(spaceSteps, "column-gap") },
    { attr: "gap-y", scope: "", values: space(spaceSteps, "row-gap") },
    { attr: "p", scope: "", values: space(spaceSteps, "padding") },
    { attr: "px", scope: "", values: space(spaceSteps, "padding-inline") },
    { attr: "py", scope: "", values: space(spaceSteps, "padding-block") },
    { attr: "pt", scope: "", values: space(spaceSteps, "padding-block-start") },
    { attr: "pb", scope: "", values: space(spaceSteps, "padding-block-end") },
    {
      attr: "direction",
      scope: STACK_INLINE,
      values: [
        ["row", "flex-direction: row"],
        ["column", "flex-direction: column"],
      ],
    },
    {
      attr: "wrap",
      scope: STACK_INLINE,
      values: [
        ["wrap", "flex-wrap: wrap"],
        ["nowrap", "flex-wrap: nowrap"],
      ],
    },
    {
      attr: "align",
      scope: STACK_INLINE_GRID,
      values: [
        ["start", "align-items: flex-start"],
        ["center", "align-items: center"],
        ["end", "align-items: flex-end"],
        ["stretch", "align-items: stretch"],
        ["baseline", "align-items: baseline"],
      ],
    },
    {
      attr: "justify",
      scope: STACK_INLINE_GRID,
      values: [
        ["start", "justify-content: flex-start"],
        ["center", "justify-content: center"],
        ["end", "justify-content: flex-end"],
        ["between", "justify-content: space-between"],
      ],
    },
    {
      attr: "columns",
      scope: GRID,
      values: numbered(
        ["1", "2", "3", "4", "5", "6", "12"],
        (n) => `grid-template-columns: repeat(${n}, minmax(0, 1fr))`,
      ),
    },
    {
      attr: "text-align",
      scope: TEXT,
      values: [
        ["start", "text-align: start"],
        ["center", "text-align: center"],
        ["end", "text-align: end"],
      ],
    },
    {
      attr: "span",
      scope: "",
      values: [
        ...numbered(["1", "2", "3", "4", "5", "6"], (n) => `grid-column: span ${n} / span ${n}`),
        ["full", "grid-column: 1 / -1"],
      ],
    },
    {
      attr: "hidden",
      scope: "",
      values: [
        ["true", "display: none"],
        ["false", "display: revert-layer"],
      ],
    },
  ]
}

function block(rules: PropRule[], prefix: string, indent: string): string {
  const lines: string[] = []
  for (const rule of rules) {
    for (const [token, declaration] of rule.values) {
      lines.push(`${indent}${rule.scope}[data-${rule.attr}~="${prefix}${token}"] { ${declaration}; }`)
    }
  }
  return lines.join("\n")
}

export function generatePropsCss(tokensCss: string): string {
  const { breakpoints, spaceSteps } = readScales(tokensCss)
  const rules = propRules(spaceSteps)
  let css = "/* props.css. GENERATED from tokens.css by src/gen/props-css.ts. */\n"
  css += "@layer rp.props {\n"
  css += block(rules, "", "  ") + "\n"
  for (const [name, minWidth] of Object.entries(breakpoints)) {
    css += `  @media (min-width: ${minWidth}) {\n`
    css += block(rules, `${name}:`, "    ") + "\n"
    css += "  }\n"
  }
  css += "}\n"
  return css
}
```

### 6.5 Behaviour that component authors and bindings rely on

1. Token order inside the attribute does not matter. Two tokens for the same breakpoint are an error reported by the checker, not by CSS.
2. When the attribute has no unprefixed token, the component's own default applies below the first breakpoint named.
3. A layout prop overrides the component's own declaration of the same property (layer order). A utility class overrides the prop.
4. A scoped attribute on an element outside its scope has no effect. The checker reports it.
5. `data-hidden` and `data-span` work on any element, including component roots that are not layout primitives.
6. An element whose static display is `contents` (section 4.3) MUST NOT carry a layout prop.

## 7. Component CSS

### 7.1 The styling contract

Fixed by `00-decisions.md` D-024 and section 4.3; restated here only as far as CSS authors need it.

- A component root has class `rp-<component id>`. A styled part has class `rp-<component id>-<part>`. Ripple prints no other class.
- An enumerated prop is `data-<prop>="<value>"` and the default value is printed too. A boolean prop is `data-<prop>=""` when true and absent when false.
- State is expressed by the attributes of D-021: `open`, `hidden`, `disabled`, `checked`; `aria-expanded`, `aria-selected`, `aria-current`, `aria-invalid`, `aria-busy`, `aria-disabled`; `data-open`, `data-closed`, `data-disabled`, `data-pending`, `data-selected`, `data-checked`, `data-active`, `data-current`.

### 7.2 File skeleton

Every `components/<id>/<id>.css` MUST have exactly this structure. A section with no rules keeps its comment line.

```css
/* <id>.css
   Component: <ComponentName> (id `<id>`). Contract: <NN-doc-name>.md, "<ComponentName>".
   Root:      <element(s)>, class rp-<id>
   Parts:     rp-<id>-<part> (<element>), one line per part; omit the line when there are none
   Props:     data-<prop> = <value> | <value>   (default <value>), one line per styled prop
   States:    <selectors used in section 4>
   Public:    --rp-<id>-<name>, comma separated; "none" when there are none */
@layer rp.components {
  /* 1. ROOT */
  .rp-<id> {
    /* 1a. public custom properties */
    /* 1b. colour slots */
    /* 1c. other private custom properties */
    /* 1d. declarations */
  }

  /* 2. PARTS */

  /* 3. MODIFIERS */

  /* 4. STATES */

  /* 5. MOTION */

  /* 6. ENVIRONMENT */
}
```

| Section | Contains | Selector forms allowed |
|---|---|---|
| 1 ROOT | one rule; custom property declarations first (1a, 1b, 1c), then real declarations (1d) | `.rp-<id>` |
| 2 PARTS | one rule per part; real declarations; MAY declare private custom properties | `.rp-<id>-<part>`; inside RichText-like components only: `.rp-<id> :where(<tag>)` |
| 3 MODIFIERS | one rule per non-default prop value; custom property declarations ONLY | `.rp-<id>[data-<prop>="<value>"]`, `.rp-<id>[data-<prop>]` (boolean), and the same forms on a part class |
| 4 STATES | real declarations that read slots; fixed order: hover, active, focus, disabled, pending, then other state attributes | `.rp-<id>:hover` (inside `@media (hover: hover)`), `:active`, `:focus-visible`, `:focus-within`, `:disabled`, `:checked`, `:placeholder-shown`, `:user-invalid`, `[open]`, `::backdrop`, `::after`, `::before`, `::marker`, `::placeholder`, an attribute from the state list of 7.1, and `:is()` / `:not()` over these; the same on a part class; a root state followed by a descendant part: `.rp-<id>[open] .rp-<id>-<part>` |
| 5 MOTION | one `@media (prefers-reduced-motion: no-preference) { ... }` block holding every `transition` and `animation`; `@keyframes rp-<id>-<name>` | any form allowed in sections 1 to 4 |
| 6 ENVIRONMENT | `@supports`, `@media (min-width: ...)`, `@media (forced-colors: active)`, `@media (scripting: none)`, `@container` blocks | any form allowed in sections 1 to 4 |

### 7.3 Rules

Each rule has an id. Rules marked "lint" are enforced mechanically by `lintComponentCss` (section 7.9) and fail `pnpm gen --check`.

| Id | Rule | Lint |
|---|---|---|
| CSS-01 | The file is one header comment followed by one `@layer rp.components { ... }` block. Nothing else at the top level (the provenance trailer is added at scaffold time and is ignored by the linter). | lint |
| CSS-02 | Every selector begins with `.rp-<id>` or `.rp-<id>-<part>` of the file's own component. | lint |
| CSS-03 | No class of another component, no utility class, no id selector, no bare tag selector. A tag selector MAY appear only inside `:where()` after the file's own class (`.rp-rich-text :where(h2)`). | lint |
| CSS-04 | None of: `!important`, nesting, `@apply`, `@utility`, `@variant`, `theme(`, `@import`, `@property`, a second `@layer`. | lint |
| CSS-05 | No selector contains `data-rp-`, `data-slot`, `data-state`, `data-agent-`, `data-rmx-` or `data-scheme`. | lint |
| CSS-06 | A modifier rule (section 3 of the file) contains custom property declarations only. The base rule consumes them. | lint |
| CSS-07 | Every `data-<prop>` selected in a modifier rule is a prop of the component in the manifest, and every `"<value>"` is one of its values. The default value has no modifier rule: the root rule is the default. | lint |
| CSS-08 | Colour slots: a component with `tone` or `variant` colours consumes exactly three private colour slots in its real declarations: `--_bg` (background), `--_fg` (text and icons), `--_border` (border colour). | lint (names) |
| CSS-09 | Every private custom property a file reads is declared in that file's root rule. (Custom properties inherit; an undeclared slot would take the value of an enclosing component.) | lint |
| CSS-10 | A public custom property is named `--rp-<id>-<name>`, is declared in the root rule with a default built from tokens, and is listed on the `Public:` line of the header. The header list and the declared set are equal. | lint |
| CSS-11 | Real declarations read only: the file's own public and private custom properties, and tokens declared in `tokens.css`. A `var()` naming any other custom property is an error. | lint |
| CSS-12 | No colour literal (hex, `rgb(`, `hsl(`, `oklch(`, `oklab(`, `color(`, named colours). Allowed: `transparent`, `currentColor`, `color-mix()` over allowed values, and system colour keywords inside `@media (forced-colors: active)`. | lint |
| CSS-13 | No length literal in `px`, `rem`, `vw`, `vh`. Allowed: `0`, `1px`, `2px` (borders and outlines), `9999px` (round), any `em`, `ch`, `%`, `fr`, `dvh` value, unitless numbers. Every other length is a token or a `calc()` over tokens. | lint |
| CSS-14 | Logical properties and values only (section 10). | lint |
| CSS-15 | `transition`, `transition-*`, `animation`, `animation-*` and `scroll-behavior` appear only inside `@media (prefers-reduced-motion: no-preference)`. | lint |
| CSS-16 | `@media (min-width: X)` is allowed only with `X` equal to a `--breakpoint-*` value of `tokens.css`. `max-width` media queries MUST NOT be used (mobile-first). | lint |
| CSS-17 | `:hover` appears only inside `@media (hover: hover)`. | lint |
| CSS-18 | `outline: none`, `outline: 0`, `outline-style: none` and `outline-width: 0` are prohibited, except in a `:focus-visible` rule of a part when the same file has a `:focus-within` rule that declares `outline` with `var(--color-ring)` (section 11 rule 4). | lint |
| CSS-19 | `z-index` values are `var(--rp-z-raised)`, `var(--rp-z-sticky)`, `var(--rp-z-overlay)`, `var(--rp-z-toast)` or `auto`. | lint |
| CSS-20 | `@keyframes` names are `rp-<id>-<name>`. `rp-spin` and `rp-pulse` MAY be used but not redefined. | lint |
| CSS-21 | Selector specificity is at most (0,3,1). | lint |
| CSS-22 | State selectors select both forms where both exist, so that server HTML and the upgraded element look the same: `:is(:disabled, [aria-disabled="true"])`, `:is([data-pending], [aria-busy="true"])`, `:is([data-selected], [aria-selected="true"])`, `:is([data-open], [open], [aria-expanded="true"])`. `:defined` MUST NOT be used in component CSS. | review |
| CSS-23 | A state that replaces content MUST NOT change the size of the box (Button `pending` hides the label with `color: transparent` and draws the spinner in `::after`). | test A-07 |
| CSS-24 | A component MUST NOT rely on Tailwind preflight. It resets on its own root whatever it needs. | test A-12 |
| CSS-25 | A component MUST NOT style another component by selector. To adjust a child component it sets that component's PUBLIC custom property on its own root or part (for example a toolbar sets `--rp-button-height`). | lint (via CSS-02, CSS-03) |
| CSS-26 | Every filled control has `border: 1px solid var(--_border)`, with `--_border: transparent` when it has no visible border. Reason: forced-colours mode draws transparent borders, which keeps the control's edge visible. | review |
| CSS-27 | One declaration per line. One selector per line in a selector list. Two-space indent. (Keeps three-way merges on `ripple upgrade` small.) | lint |
| CSS-28 | The file, minified with the options of section 5.4, is at most 6,000 bytes (section 14). | size runner |
| CSS-29 | `:empty` MUST NOT be used (hosts differ in whitespace between elements; `02-html-contract.md`, canonicalisation). | lint |

How it works:

1. `variant` rules write only `--_bg`, `--_fg`, `--_border` and, for `link`, the private and public variables that remove the box. `size` rules write only public dimensions. `data-full-width` writes only `--_display` and `--_inline-size`. The sets are disjoint, so any combination of the 6 variants, 3 sizes and `fullWidth` composes without a combination rule and without depending on rule order.
2. One hover rule serves every variant: `color-mix(in oklab, var(--_bg) var(--_hover), var(--_fg))`. With a filled `--_bg` it moves the fill 12% toward the text colour. With `--_bg: transparent` it yields the text colour at 12% opacity (verified: `oklab(0.21 0.0017 -0.0058 / 0.12)` for `outline` in the light scheme). `link` sets `--_hover: 100%`, which leaves the background transparent.
3. There is no `:focus-visible` rule: the ring comes from `base.css` (section 11).
4. `pending` keeps the width (verified equal to the non-pending width) and shows a static ring when motion is reduced.
5. The contrast of label on fill is at least 4.5:1 for all six variants in `light` and `dark` (verified; minimum 5.79 for `destructive` in `light`).

| `[data-size="md"]` | `min-block-size` | 44 px |
| `[data-size="lg"]` | `min-block-size` | 52 px |
| `[data-variant="link"]` | `min-block-size`, `padding-inline`, `text-decoration-line` | 24 px, 0, `underline` |
| `[data-variant="primary"]` | `background-color`, `color` | computed `--color-primary`, computed `--color-primary-foreground` |
| `[data-variant="outline"]` | `border-color` | computed `--color-input` |

| `[hidden]` | `display` | `none` |

| root, reduced motion | `transition-duration`; `::after` `animation-name` when pending | `0s`; `none` |

### 7.5 Components with `tone`

`tone` values are `neutral muted primary info success warning destructive sale` (`00-decisions.md` 6.3); a component uses a subset.

A tone has three inputs, because a tone used as a fill, the text on that fill, and the tone used as text on the page are three different colours (a light brand colour is not readable as text):

| `tone` | `--_tone` (fill) | `--_on-tone` (text on the fill) | `--_tone-text` (the tone as text) |
|---|---|---|---|
| `neutral` | `var(--color-foreground)` | `var(--color-background)` | `var(--color-foreground)` |
| `muted` | `var(--color-muted)` | `var(--color-muted-foreground)` | `var(--color-muted-foreground)` |
| `primary` | `var(--color-primary)` | `var(--color-primary-foreground)` | `var(--color-foreground)` |
| `info` | `var(--color-info)` | `var(--color-info-foreground)` | `var(--color-info)` |
| `success` | `var(--color-success)` | `var(--color-success-foreground)` | `var(--color-success)` |
| `warning` | `var(--color-warning)` | `var(--color-warning-foreground)` | `var(--color-warning)` |
| `destructive` | `var(--color-destructive)` | `var(--color-destructive-foreground)` | `var(--color-destructive)` |
| `sale` | `var(--color-sale)` | `var(--color-sale-foreground)` | `var(--color-sale)` |

**A component with `tone` only** (Text, FormMessage, Price parts) colours text. Its tone modifier sets `--_fg` to the `--_tone-text` column directly:

```css
.rp-text[data-tone="destructive"] {
  --_fg: var(--color-destructive);
}
```

**A component with `tone` and `variant`** (Badge, Banner; variants from `solid soft outline plain elevated`) uses two sets of modifier rules that write disjoint variables:

- a tone rule writes the three tone inputs `--_tone`, `--_on-tone`, `--_tone-text` (declared in section 1c of the root rule with the values of the component's default tone);
- a variant rule writes the three colour slots from the tone inputs, with exactly these formulas:

| `variant` | `--_bg` | `--_fg` | `--_border` | Other |
|---|---|---|---|---|
| `solid` | `var(--_tone)` | `var(--_on-tone)` | `transparent` | |
| `soft` | `color-mix(in oklab, var(--_tone-text) 12%, transparent)` | `var(--_tone-text)` | `transparent` | |
| `outline` | `transparent` | `var(--_tone-text)` | `color-mix(in oklab, var(--_tone-text) 45%, transparent)` | |
| `plain` | `transparent` | `var(--_tone-text)` | `transparent` | |
| `elevated` | `var(--color-card)` | `var(--color-card-foreground)` | `var(--color-border)` | `--_shadow: var(--shadow-sm)` (declared `none` in the root rule) |

Verified: for the 8 tones x `solid`, `soft`, `outline`, `plain` in `light` and `dark`, text contrast is at least 4.5:1 (minimum 4.59, `success` `soft` in `light`).

Pattern (excerpt; the complete Badge file is specified in `09-components-foundation.md`):

```css
@layer rp.components {
  /* 1. ROOT */
  .rp-badge {
    /* 1b. colour slots */
    --_bg: var(--_tone);
    --_fg: var(--_on-tone);
    --_border: transparent;
    /* 1c. other private custom properties */
    --_tone: var(--color-foreground);
    --_on-tone: var(--color-background);
    --_tone-text: var(--color-foreground);
    /* 1d. declarations */
    border: 1px solid var(--_border);
    background-color: var(--_bg);
    color: var(--_fg);
  }

  /* 3. MODIFIERS */
  .rp-badge[data-tone="sale"] {
    --_tone: var(--color-sale);
    --_on-tone: var(--color-sale-foreground);
    --_tone-text: var(--color-sale);
  }

```

Button has no `tone` (D-031); its `variant` rules write the colour slots directly from tokens, as in 7.4.

### 7.6 Sizes

| `size` (controls) | Height token | Use |
|---|---|---|
| `sm` | `--spacing-control-sm` | Button, IconButton, Input, Select, Textarea (min height), QuantityInput |
| `md` | `--spacing-control-md` | same; the default |
| `lg` | `--spacing-control-lg` | same |

1. A control's height is `min-block-size: var(--rp-<id>-height)`, never `height` or `block-size`, so that wrapped or enlarged text grows the control.
2. Controls in one row line up because they share these three tokens. A component MUST NOT define its own height scale.
3. A size modifier writes public dimension variables only (`--rp-<id>-height`, `--rp-<id>-px`, `--rp-<id>-font-size`, `--rp-<id>-gap`).
4. Every interactive element MUST be at least `var(--spacing-target-min)` (24 px) in both dimensions, or have that much hit area through padding.

### 7.7 Layout defaults and layout props

A layout component declares its default layout in its root rule (for example `.rp-stack { display: flex; flex-direction: column; }`). Layout props then override single properties from layer `rp.props`. Component CSS MUST NOT contain rules for `data-gap`, `data-p`, `data-px`, `data-py`, `data-pt`, `data-pb`, `data-gap-x`, `data-gap-y`, `data-direction`, `data-wrap`, `data-align`, `data-justify`, `data-columns`, `data-text-align`, `data-span` or `data-hidden`: those belong to `props.css` only.

### 7.8 Pre-upgrade parity

1. The look before upgrade MUST equal the look after upgrade. This follows from CSS-22 (both state forms selected), the static display rules (section 4.3) and the upgrade-stable contract (`02-html-contract.md`).
2. Component CSS MUST NOT use `:defined` or `:not(:defined)`. Only the generated script-state rules do.
3. Closed overlay content is hidden by the `hidden` attribute or by the browser (`<dialog>` without `open`, `[popover]` not shown, closed `<details>`), never by a class or by component CSS that depends on script.

### 7.9 The linter

`src/gen/css-lint.ts` exports:

```ts
export interface CssLintContext {
  /** Component id, for example "button". */
  id: string
  /** Part names from the manifest, for example ["title", "panel"]. */
  parts: string[]
  /** Styled props from the manifest: prop attribute name (without data-) to allowed values; [] for a boolean prop. */
  props: Record<string, string[]>
  /** Default value per prop attribute name. */
  defaults: Record<string, string>
  /** Text of css/tokens.css (source of token names and breakpoint values). */
  tokensCss: string
}

export interface CssLintFinding {
  /** Rule id from section 7.3, for example "CSS-06". */
  rule: string
  /** 1-based line in the file. */
  line: number
  message: string
}

export function lintComponentCss(css: string, context: CssLintContext): CssLintFinding[]
```

Requirements:

1. It implements every rule marked "lint" in 7.3. It has no dependency: it tokenises the file with a brace-and-semicolon scanner (the format rules CSS-04 and CSS-27 make this sufficient).
2. It ignores a trailing provenance trailer comment.
3. `pnpm gen --check` runs it over every `components/<id>/<id>.css` and exits 1 when any finding exists, printing `<file>:<line> <rule> <message>` per finding.
4. Its own tests (`src/gen/css-lint.test.ts`) MUST include: the Button file of 7.4 produces zero findings; and for each lint rule one minimal failing file that produces exactly one finding with that rule id.

## 8. Motion and reduced motion

1. **Opt-in motion.** Every `transition` and `animation` declaration MUST be inside `@media (prefers-reduced-motion: no-preference)` (CSS-15). With `prefers-reduced-motion: reduce`, every state change applies instantly and nothing loops. Ripple MUST NOT use a global rule that zeroes durations; there is nothing to zero.
2. **Tokens only.** Durations and easings come from `tokens.css`:

   | Motion | Duration | Easing |
   |---|---|---|
   | hover, press, colour, border, opacity of a control | `var(--rp-duration-fast)` | `var(--ease-out)` |
   | exit of an overlay, collapse, small reveal | `var(--rp-duration-base)` | `var(--ease-out)` |
   | entrance of a dialog, popover, tooltip, toast | `var(--rp-duration-slow)` | `var(--ease-out)` |
   | entrance and exit of a drawer or sheet | `var(--rp-duration-slow)` in, `var(--rp-duration-base)` out | `var(--ease-drawer)` |
   | an element moving between two positions (tab indicator, carousel) | `var(--rp-duration-base)` | `var(--ease-in-out)` |
   | spinner | `calc(var(--rp-duration-slow) * 2)`, `linear`, `infinite`, keyframes `rp-spin` | |
   | skeleton pulse | `calc(var(--rp-duration-slow) * 5)`, `var(--ease-in-out)`, `infinite`, keyframes `rp-pulse` | |

3. **Properties.** Transitions and animations MUST be limited to `opacity`, `translate`, `scale`, `rotate`, `background-color`, `color`, `border-color`, `box-shadow`, `outline-color`, and, for top-layer elements, `display` and `overlay` with `transition-behavior: allow-discrete`. `transition: all` MUST NOT be used. Layout properties (`width`, `height`, `inline-size`, `block-size`, `margin`, `padding`, `inset`) MUST NOT be animated. The individual transform properties `translate`, `scale`, `rotate` MUST be used instead of `transform`.
4. **Native overlays** (`<dialog>`, `[popover]`): entrance uses `@starting-style`; exit uses `transition-behavior: allow-discrete` on `display` and `overlay`. A browser that does not support these shows and hides the element instantly, which is the working fallback; no `@supports` is required.
5. **UI SDK elements** (Tabs, Tooltip, Toast): entrance styles select `[data-starting-style]` and exit styles select `[data-ending-style]`, as documented by UI SDK (`uisdk/apps/docs/content/docs/web-components/styling-and-animation.mdx`: "Put exit styles on `data-ending-style`; `data-closed` describes state but doesn't wait for an exit"). These two attributes MAY be selected only in the CSS of those three components.
6. **Press feedback.** Button and IconButton scale to `0.97` while `:active`. No other component scales on press.
7. **Scrolling.** `scroll-behavior: smooth` is allowed only inside the motion media query.
8. **No box change.** A pending or loading state MUST NOT change the size of its box (CSS-23).
9. **Hover** styles are inside `@media (hover: hover)` (CSS-17), so touch devices show no stuck hover state.

## 9. Colour, contrast and forced colours

1. Text and icons that convey meaning MUST have at least 4.5:1 contrast against their background; form control borders and the focus ring at least 3:1. The default tokens meet this (table in 3.4). A component meets it by using a role with its own `-foreground` partner, or `--_tone-text` on the page background.
2. A component MUST NOT place `--color-primary`, `--rp-brand` or `--rp-accent` as text on `--color-background`; the brand is not guaranteed readable as text. Text uses `--color-foreground`, `--color-muted-foreground`, `--color-link` or a status colour.
3. Disabled controls use `opacity: 0.5` and are exempt from contrast requirements.
4. A state MUST NOT be conveyed by `background-color` alone. Selected, checked, current and invalid states MUST also change a border, an outline, an icon or the font weight, so that they survive `forced-colors: active`.
5. Component CSS MAY add a `@media (forced-colors: active)` block in section 6 that uses system colour keywords (`CanvasText`, `Canvas`, `ButtonText`, `Highlight`, `HighlightText`, `GrayText`). It MUST NOT set `forced-color-adjust: none`, except on colour swatches whose colour is the content.
6. Component CSS MUST NOT reference a scheme. A component is correct in every scheme because every colour it reads is a derived token.

## 10. Logical properties and right-to-left

Ripple CSS MUST use logical properties and values only. `start` and `end` are the only direction words in prop values, class names, part names and custom property names; `left` and `right` MUST NOT appear.

| Prohibited (lint CSS-14) | Use |
|---|---|
| `margin-left`, `margin-right` | `margin-inline-start`, `margin-inline-end` |
| `margin-top`, `margin-bottom` | `margin-block-start`, `margin-block-end` |
| `padding-left`, `padding-right`, `padding-top`, `padding-bottom` | `padding-inline-start`, `padding-inline-end`, `padding-block-start`, `padding-block-end` |
| `left`, `right`, `top`, `bottom` | `inset-inline-start`, `inset-inline-end`, `inset-block-start`, `inset-block-end` (`inset: 0` is allowed) |
| `width`, `height`, `min-width`, `max-width`, `min-height`, `max-height` | `inline-size`, `block-size`, `min-inline-size`, `max-inline-size`, `min-block-size`, `max-block-size` |
| `border-left`, `border-right`, `border-top`, `border-bottom` and their `-color`, `-width`, `-style` forms | `border-inline-start`, `border-inline-end`, `border-block-start`, `border-block-end` and their longhands |
| `border-top-left-radius`, `border-top-right-radius`, `border-bottom-left-radius`, `border-bottom-right-radius` | `border-start-start-radius`, `border-start-end-radius`, `border-end-start-radius`, `border-end-end-radius` |
| `text-align: left`, `text-align: right` | `text-align: start`, `text-align: end` |
| `float`, `clear` | not used; lay out with flex or grid |
| `overflow-x`, `overflow-y` | `overflow-inline`, `overflow-block` are not in the browser floor: `overflow-x` and `overflow-y` are ALLOWED (the one exception in this table) |
| `scroll-margin-left`, `scroll-padding-left` and the other physical scroll longhands | `scroll-margin-inline-start`, `scroll-padding-inline-start` and the other logical longhands |
| `transform` | `translate`, `scale`, `rotate` |

Physical quantities with no logical form use the token `--rp-dir` (`1`; `-1` inside `[dir="rtl"]`):

| Need | Write |
|---|---|
| Slide in from the inline end (drawer `side="end"`) | closed position `translate: calc(100% * var(--rp-dir)) 0` |
| Slide in from the inline start (drawer `side="start"`) | closed position `translate: calc(-100% * var(--rp-dir)) 0` |
| Mirror a directional icon (`arrow-left`, `arrow-right`, `chevron-left`, `chevron-right`) | `scale: var(--rp-dir) 1` |
| Centre with a physical offset | not allowed; use `inset-inline: 0; margin-inline: auto` or grid `place-items: center` |

Rules:

1. Component CSS MUST NOT contain a `[dir]` selector or `:dir()`. Direction reaches CSS only through logical properties and `--rp-dir`.
2. Flex and grid follow the writing direction automatically; `row-reverse` MUST NOT be used to fake direction.
3. `props.css` uses logical padding properties (section 6.1); `data-px` is inline padding in both directions.
4. The host sets `dir` on `<html>` (or on any subtree). Bindings wrap user-generated text of unknown direction in `<bdi>` (`06-bindings.md`).

## 11. Focus

1. **One global ring.** `base.css` gives every element that matches `:focus-visible` this ring, at zero specificity:

   ```css
   :where(:focus-visible) {
     outline: var(--rp-ring-width) solid var(--color-ring);
     outline-offset: var(--rp-ring-offset);
   }
   ```

   It applies to Ripple components, to native controls and to escape-hatch markup alike. Components MUST NOT repeat it.
2. **Never removed.** Component CSS MUST NOT remove the outline (CSS-18). `base.css` removes it for exactly two targets of programmatic focus: `dialog` and `main` (`:where(dialog, main):focus-visible { outline: none; }`); focus inside them is visible on the focused control.
3. **Allowed adjustments** in a component's `:focus-visible` rule (section 4 of the file): `outline-offset` and `border-radius` only.
   - Inside a container that clips (`overflow` other than `visible`: carousel slides, scroll areas, accordion triggers flush with their container), use `outline-offset: calc(var(--rp-ring-width) * -1)` so the ring is drawn inside the box.
   - An element stacked under a sibling MAY set `z-index: var(--rp-z-raised)` in its `:focus-visible` rule so the ring is not covered.
4. **Moving the ring to a wrapper.** When a control sits inside a styled wrapper that should show the ring (an input with an inline button, the quantity stepper), the wrapper declares the ring with `:focus-within` and only then may the inner control remove its own:

   ```css
   .rp-quantity:focus-within {
     outline: var(--rp-ring-width) solid var(--color-ring);
     outline-offset: var(--rp-ring-offset);
   }
   .rp-quantity-input:focus-visible {
     outline: none;
   }
   ```

   Buttons inside such a wrapper keep their own ring with a negative offset.
5. **`:focus-visible`, not `:focus`.** Component CSS MUST NOT style `:focus`. Text inputs match `:focus-visible` on pointer focus too; that is intended.
6. **Colour.** The ring colour is `--color-ring` (the foreground colour; at least 3:1 against `--color-background` in every scheme that meets rule 9.1). On a filled control the 2 px offset places the ring on the surrounding background, so it never sits on the fill.
7. **Forced colours.** `outline-color` is replaced by a system colour automatically; the ring MUST be an `outline`, never a `box-shadow`, so that it survives.
8. **Roving focus** (Tabs, RadioGroup): an item that receives focus by arrow key matches `:focus-visible` and shows the ring; no component may suppress it on `[tabindex="-1"]`.

## Ledger issues

Decisions this document had to make because the ledger is silent, and places where following the ledger literally does not work.

1. **Script-state rules are in layer `rp.props`, not `rp.base`** (D-021 item 4 says "generated rules in `base.css`"). They stay in the file `base.css` but inside an `@layer rp.props` block. In `rp.base` they lose to any component `display` rule in `rp.components` (for example a `.rp-button` carrying `data-rp-js="fallback"`), and `!important` is not allowed.
2. **`data-text-align` added to `props.css`** between `columns` and `span` (D-028 item 4 lists a fixed order without it; section 6.3 of the ledger makes `textAlign` responsive on Heading, Text, Stack). Scoped `:where(.rp-heading, .rp-text, .rp-stack)`. The gzip budget of 5.2 kB still holds (5,037 bytes).
3. **Modifiers set custom properties only, with no "structural modifier" exception** (D-024 item 2 read literally). Boolean props therefore work through private variables (`--_display`, `--_inline-size`), and the selector form `.rp-<id>[data-<prop>]` is added for boolean props.
4. **Tone inputs.** Section 4.5 of the ledger says a component "consumes exactly three private slots `--_bg`, `--_fg`, `--_border`". Components with both `tone` and `variant` need three more private variables that the modifier rules (not the real declarations) use: `--_tone`, `--_on-tone`, `--_tone-text`. Other private non-colour variables (`--_hover`, `--_display`, `--_decoration`, `--_shadow`) are also allowed.
5. **Tokens added that the ledger does not list**: `--color-sale-foreground` and `--color-link` values; `--spacing-target-min` (24 px, from D-066); `--font-weight-normal|medium|semibold|bold`; `--rp-heading-weight`; `--rp-ring-width`, `--rp-ring-offset`; `--rp-dir`; `--rp-space-steps` (generator input); `--breakpoint-*` are declared in `tokens.css` as the breakpoint source. `--shadow-xl` from the spike is dropped (D-029 lists `xs` to `lg`).
6. **Scheme blocks set `--rp-brand-foreground`** (`initial` in `light`, a literal in `dark`), and a static block gives dark status colours. Reason: on Chrome 111 to 118 (inside the floor, no relative colour syntax) the dark scheme's near-white brand would otherwise get white text.
7. **The host token bridge prints two rules, not one** (D-026 item 5 says "one inline `:root { ... }` rule"): non-colour dials on `:root`, colour dials on `:root, [data-scheme="light"]`. With `:root` alone, a `scheme="light"` component inside a dark section would show Ripple's stock colours instead of the merchant's. Doc 14 owns the Liquid source.
8. **No built-in scheme follows the operating system** (the spike had `data-scheme="auto"`; D-026 names only `light` and `dark`). Section 3.6 item 6 gives the block a project adds.
9. **No CLI command regenerates `props.css` and `theme.css` after a project edits `tokens.css`** (D-029 says "editing `tokens.css` and re-running the generator"; D-057 has no such command). This document assigns it to `ripple add` and `ripple upgrade`; doc 07 must confirm or add a command.
10. **Files added to the repository tree of ledger 5.1**: `src/gen/tokens-source.ts`, `src/gen/css-lint.ts`, `src/gen/css-lint.test.ts`. `base.css` is "hand-written" in the tree but has two generated marker regions (`display`, `script-state`).
11. **The manifest has no key for an element's static display value** (section 4.8 of the ledger). Section 4.3 gives initial values; doc 07 must define the key.
12. **`theme.css` is imported by the project's entry after `tailwindcss`**, not from `ripple.css` (D-055 item 1 mentions only `ripple.css` then `tailwindcss`).
13. **A per-component CSS budget** (6,000 bytes minified) is added; D-064 has only aggregate budgets.
